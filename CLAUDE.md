# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
just setup          # Install dev deps via uv sync (creates .venv)
just check          # Run lint + format check + tests (full CI equivalent)
just test           # Run tests
just test-v -k foo  # Run tests matching keyword "foo" with verbose output
just lint           # Lint with ruff
just lint-fix       # Auto-fix lint issues
just fmt            # Format with ruff
just build          # Build the package (dist/)
just check-completions  # Verify bash/zsh completion scripts parse
```

All tasks can also be run without `just` via `uv run <tool>`:
```bash
uv run pytest -v
uv run ruff check src/ tests/
uv run kdebug --help
```

## Architecture

Single-file CLI: all logic lives in `src/kdebug/cli.py` (~1400 lines). No external runtime dependencies — Python stdlib only.

**Entry point**: `kdebug.cli:main` (registered in `pyproject.toml` `[project.scripts]`)

**Version**: Single source of truth in `pyproject.toml`, read at runtime via `importlib.metadata`.

**Global state** set after argparse runs: `DEBUG_MODE`, `KUBECTL_CONTEXT`, `KUBECTL_KUBECONFIG`.

**kubectl integration**:
- All kubectl commands are built with `kubectl_base_cmd()` to ensure `--context`/`--kubeconfig` are passed through.
- `run_command()` wraps `subprocess.run` with `check=False` — stderr is silently discarded on failure.
- `validate_cluster_connection()` uses `subprocess.run` directly to capture and surface stderr for early diagnostics.
- All kubectl queries use `-o json` and parse with `json.loads()`.

**Subcommands**: `debug` (default, interactive shell) and `backup` (copy files from pod), implemented via `argparse.add_subparsers()`. Shared args live on the main parser so bare `kdebug --pod foo` works.

**Pod selection**: direct (`--pod`), controller-based (`--controller` for Deployments/StatefulSets/DaemonSets), or interactive TUI.

**Colors**: `colorize()` function + `Colors` class (ANSI codes). Pattern: `{colorize('✓', Colors.GREEN)}` for success, `{colorize('✗ Error:', Colors.RED)}` for errors. Error messages go to `sys.stderr`.

**Completion scripts**: `src/kdebug/completions/kdebug.bash` and `src/kdebug/completions/_kdebug` are generated by `generate_bash_completion()` and `generate_zsh_completion()` in `cli.py`. Regenerate with:
```bash
kdebug --completions bash > src/kdebug/completions/kdebug.bash
kdebug --completions zsh > src/kdebug/completions/_kdebug
```

## Adding a New CLI Argument

1. Add to the appropriate `parser.add_argument_group()` in `main()`
2. Update `generate_bash_completion()` — add to `opts` list and completion case
3. Update `generate_zsh_completion()` — add to `args` array with appropriate completer
4. Regenerate completion files
5. Update `README.md` if user-facing

## Code Conventions

- `E501` (line length) is ignored — long colorized f-strings stay on one line
- `run_command()` for shell execution; `print_debug_command()` to log commands when `--debug` is on
- Config file at `~/.config/kdebug/kdebug.json` (respects `XDG_CONFIG_HOME`); CLI flags always override
